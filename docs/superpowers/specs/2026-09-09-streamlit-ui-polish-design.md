# Streamlit UI Polish Design

> 日期：2026-09-09  
> 分支：`feature/chinese-job-pipeline`

## 目标

将岗位 Agent 的 Streamlit 云端界面从“功能可用的表单页”提升为“可公开演示的 AI 工作台”，保留现有运行能力、数据边界和下载产物，不改变岗位发现、抽取、验证、匹配与持久化逻辑。

## 用户体验方向

采用 A「清爽工作台」方向：浅色主界面、深墨绿色品牌色、深色侧栏、白色卡片、清晰的运行状态和结果层级。首屏让用户先理解系统做什么，再配置任务；运行后优先看到有效岗位、匹配分和可解释证据。

## 页面结构

1. **品牌头部**
   - 展示产品名、简短定位和当前运行状态。
   - 用小型状态徽标区分“待运行”“运行中”“已完成”和“有失败页面”。
   - 保留 Streamlit 默认功能，不覆盖其错误和 loading 反馈。

2. **侧栏运行设置**
   - 分组展示“数据来源”“模型能力”“高级设置”。
   - 数据模式仍使用现有四种模式：内置 Demo、实时岗位、聚合岗位、指定岗位 URL。
   - 保留现有 provider 选择与凭据安全边界，只改善说明文字和视觉分组。

3. **主区任务配置卡片**
   - 关键词、地点、目标岗位数和技能标签保持现有字段。
   - 简历输入与上传放进独立区域，强调“可选”。
   - 模式相关的 URL/文件输入仅在对应模式显示。
   - 主按钮使用明确的动作文案，避免与页面标题竞争。

4. **运行结果区**
   - 顶部保留四项指标：有效岗位、访问页面、失败页面、重复岗位。
   - 指标卡统一圆角、边框、数值层级和状态色。
   - 结果 Tabs 保持现有四类：岗位结果、失败与诊断、执行轨迹、下载。
   - 岗位结果表增强视觉层级：匹配分、优先级、核验状态、梯队和类别可快速扫描；链接继续使用安全的 LinkColumn。
   - 下载区改为产物卡片，显示文件类型、用途和下载动作。

## 视觉系统

- 背景：`#F6F8F7`；内容卡片：`#FFFFFF`；侧栏：深墨绿/深灰。
- 主色：沿用并扩展现有绿色主题，强调可信、完成和可执行。
- 边框：低对比灰色；阴影只用于主要卡片，不制造过度装饰。
- 圆角：输入区和卡片 12–16px；指标卡 10–12px。
- 字体层级：页面标题 > 区块标题 > 字段标签 > 说明文本；减少连续大标题。
- 状态色：成功绿色、警告琥珀色、失败红色，不能只依靠颜色，需同时保留文字。

## 响应式规则

- 桌面端使用宽布局，任务配置和摘要信息采用两列或四列网格。
- 640px 以下：指标变为两列，配置区和结果区变为单列；宽表格允许在容器内横向滚动，不让整个页面溢出。
- 不新增前端框架或外部 CDN，样式通过 Streamlit CSS 注入和现有 `metric_grid_html` 辅助函数实现。

## 技术边界

- 主要修改：`src/web_task_agent/streamlit_app.py`、`tests/test_streamlit_app.py`、必要时 `.streamlit/config.toml`。
- 不修改：`streamlit_runner.py` 的请求模型、运行流程、凭据注入、产物白名单和数据源逻辑。
- 新增 UI 辅助函数应是纯函数或只依赖 Streamlit 已有 API，便于单测。
- 继续保留 Demo 数据诚实提示、provider 缺失提示和页面级错误诊断。

## 验收标准

- 现有核心测试全部通过。
- 新增测试覆盖：品牌头部状态文案、任务配置分组/模式说明、增强指标 HTML、下载卡片文案和移动端 CSS 规则。
- Streamlit AppTest 能完成：默认 Demo 页面渲染、模式切换到指定 URL、提交失败提示、结果区域渲染。
- 本地浏览器验证桌面和 390px 移动宽度：无横向页面溢出，运行按钮和结果入口清晰可见。
- 不改变现有运行产物、数据字段、API key 处理和结果下载安全边界。

## 不在本轮范围

- 不重写业务工作流或更换 Streamlit。
- 不接入登录、多用户权限、共享数据库、任务队列或持久化历史。
- 不把云端单实例 Demo 宣传成生产系统。
- 不新增真实招聘源或改变评测口径。
