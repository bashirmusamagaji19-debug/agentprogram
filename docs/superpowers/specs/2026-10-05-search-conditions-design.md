# 岗位搜索条件设计

用户确认地点指岗位工作地，而非 URL 字符串。多城市按 OR 匹配；岗位关键词按空格、逗号分隔，每项按 AND 命中标题或 JD，允许少量明确中英文别名（AI/人工智能、Agent/智能体、实习/intern）。不把技能标签或简历变成硬过滤条件。

运行台四种模式统一启用最终关键词与地点校验。保留历史 CLI/benchmark 的默认行为，WebTaskWorkflow 新增可选开关，仅运行台启用。结果数量在条件校验后截断，不在 seed URL 阶段提前截断。

官方与聚合发现源接收本次关键词与地点，在取目标数量前过滤已知条件。列表缺正文/地点时保留待详情验证的候选，不能据不完整列表误判。官方发现按原有三轮上限扩大采样；带条件时起始每源预算至少 5。每轮保留原始来源状态和筛选统计。运行台扫描候选预算为 min(100, max(20, target_count * 3))，不会无限抓取。

飞书/Moka 已有 keyword 字段使用本次输入；不猜测其他平台的城市 ID 或字段。无原生匹配结果时允许在既有分页上限内宽取候选，仍执行共同的客户端 AND/地点过滤。所有最终岗位再次验证，不能用不符合条件的岗位凑数。

输出保留实际搜索条件、候选预算及筛除原因，网页说明改为当前严格语义。地点仍来自正文/官方列表字段，缓存和未标注字段的边界不变。
