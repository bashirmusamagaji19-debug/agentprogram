# 真实岗位验证优化设计

## 目标

把 Web Task Agent 从以功能展示和受控 fixture 为主的作品集，优化为求职者可以连续使用、结果可追溯、指标来自真实招聘网页的岗位发现与筛选系统。本轮不增加 Agent 工具，不自动投递，不绕过登录、验证码或访问限制；主要工作是建立真实数据、失败记录、人工标注和统一评测。

目标用户是寻找国内 AI 应用、Agent、AI 工程和后端 AI 实习的求职者。首轮覆盖北京、上海、深圳、杭州和远程岗位，允许纳入大模型后端、算法工程、AI 平台、RAG 和模型服务等相邻岗位，但必须与核心岗位分层标注。

## 成功标准

第一阶段在至少 20 家企业的官方招聘页、校招官网或公开 ATS 页面上，发现并保留不少于 100 个唯一真实岗位，连续 14 天每日运行。每条岗位都能追溯到原始 URL、页面证据、首次发现时间、最后确认时间和采集方式；失败与岗位下线同样作为结果保存。

项目效果只从本轮固定、版本化的真实数据集产生。fixture 继续用于单元测试，历史 8 URL 评测、受控 Planner 场景和合成 QLoRA 数据不得与本轮指标合并。

## 方案选择

### 采用：数据与评测优先

先建立真实来源清单、每日快照、人工 ground truth 和固定对照矩阵，再形成薄的每日岗位筛选工作流。这样每项优化都能回答它改善了哪些真实样本、付出了多少成本、还留下哪些失败。

### 不采用：先做更多用户功能

自动投递、简历改写、复杂 Dashboard 和在线学习会扩大表面能力，但不会解决现有项目真实数据不足、指标代际混用和失败证据薄弱的问题。

### 不采用：同时接入所有招聘平台

首轮同时处理官网、牛客、BOSS 和拉勾，会让登录、验证码、转载真实性和反爬维护掩盖 Agent 编排与抽取质量。来源按官方页面、可追溯转载、受限平台三阶段扩展。

## 系统边界

- `Agent` 负责来源发现、页面采集、结构化抽取、验证、去重、匹配、审计和报告。
- `visual-web-agent` 只在静态 HTML 和浏览器渲染仍无法可靠抽取时提供 VLM 恢复，不默认处理所有页面。
- 人工确认负责标记岗位相关性和投递意向，不覆盖模型原始输出；任何字段修正都作为独立标注记录。
- 第一阶段只访问公开招聘页面。需要登录、验证码或明确限制时记录 `access_restricted` 并停止该次访问。
- 系统不自动提交申请、不保存招聘平台账号、不尝试规避访问控制。

## 数据设计

### 来源目录

每个来源记录：

- 公司名称与稳定标识；
- 招聘入口 URL；
- 来源类型：企业官网、校园招聘官网或公开 ATS；
- 预期城市与岗位类别；
- 当前访问状态、最后成功时间和最后检查时间；
- 访问限制和备注。

### 页面快照

每日采集结果采用追加写入，不覆盖历史。每个快照至少记录：

- 原始 URL、规范化 URL 和抓取时间；
- HTTP/浏览器状态、采集方法和最终内容指纹；
- 可公开复核的正文证据片段或证据哈希；
- 失败类型、重试次数和恢复路径；
- 页面首次发现与最后确认时间。

原始快照与结构化结果分开保存，使修复后的抽取器可以在相同输入上重放，避免因网页变化导致不公平比较。

### 结构化岗位

每条岗位至少包含公司、岗位名、地点、岗位类别、职责、要求、原始 URL、首次发现时间、最后确认时间、存活状态和来源证据。岗位类别分为：

- `core`：Agent、大模型应用、AI 应用工程；
- `adjacent`：大模型后端、算法工程、AI 平台、RAG、模型服务；
- `irrelevant`：不进入推荐，但保留验证记录。

去重同时使用公司标识、标准化岗位名、地点和正文指纹，不把 URL 当作唯一依据。官网链接变化后，应保留旧 URL 与新 URL 的关系。

### 人工标注

从真实快照中选择不少于 100 条岗位建立 ground truth。标注公司、岗位名、地点、岗位类别、职责证据、要求证据、岗位有效性和重复关系，并保留标注日期与对应证据。用于推荐评测的人工反馈另行记录为准备投递、暂不考虑、误推荐、已投递或已失效。

## 运行流程

```text
企业来源清单
  -> 检查招聘入口
  -> 发现真实岗位详情 URL
  -> 保存页面快照
  -> 静态 HTML 抽取
  -> 必要时浏览器渲染
  -> 必要时 VLM fallback
  -> 真实性与岗位类别校验
  -> 跨天、跨来源去重
  -> 与真实求职目标匹配
  -> 人工确认
  -> 当日 Top 20 投递候选清单
```

每天固定运行一次。请求保持低频、可配置和可审计。单个 URL 不无限重试；达到预算后保存失败状态。每次运行生成数据版本、阶段统计、失败分布、成本、延迟和关键产物路径。

## 失败模型

所有未成功样本必须归入明确类型：

- `source_unreachable`：招聘入口不可访问；
- `access_restricted`：登录、验证码或访问限制；
- `job_removed`：岗位已下线；
- `page_changed`：页面结构发生显著变化；
- `render_required`：静态请求无法获得有效正文；
- `extraction_incomplete`：关键字段缺失；
- `verification_rejected`：页面不是有效招聘岗位；
- `duplicate_job`：跨来源或跨日期重复；
- `model_invalid_output`：LLM/VLM 输出不满足结构或证据约束。

VLM 不能凭常识补全公司、岗位名、地点、职责或要求。结构化字段无法映射到原始页面证据时，该字段应为空或失败，而不是生成看似合理的内容。

## 评测设计

### 固定对照矩阵

在同一 URL、同一页面快照上运行三条路径：

1. 静态 HTML baseline；
2. 静态 HTML 加浏览器渲染；
3. 静态 HTML、浏览器渲染加 VLM fallback。

三条路径使用相同 ground truth 和失败定义。不得只挑选 VLM 擅长的页面，不得将不同日期或不同 URL 的结果放入同一改善结论。若 VLM 没有提升，报告应保留零提升或退化结果。

### 指标

- 有效岗位精确率：系统判定为岗位的页面中真实岗位的比例；
- 关键字段准确率：公司、岗位名、地点和岗位类别分别统计；
- 证据支持率：职责和要求能否映射到原始页面证据；
- 去重 precision、recall 和 F1；
- 岗位新鲜度：岗位状态变化到被系统识别的时间；
- 恢复成功率：baseline 失败后由浏览器或 VLM 恢复的比例；
- Top-K 相关性：每日 Top 20 中被用户标为核心或相邻目标的比例；
- 运行可靠性：14 天内产生完整审计报告的天数；
- 单岗位请求次数、模型调用次数、Token、延迟和估算成本。

任务完成率、循环终止率、工具成功率、字段准确率和用户相关性是不同指标，报告与简历不得互换表述。

### 验收门槛

- 至少 20 家官方来源、100 个唯一真实岗位和 14 个每日快照；
- 公司和岗位名准确率不低于 98%；
- 地点与岗位类别准确率不低于 90%；
- 有效岗位精确率不低于 95%；
- 去重 F1 不低于 90%；
- 全部失败记录具有明确失败类型；
- 相同快照重复执行产生的新增重复记录为 0；
- 每日 Top 20 中至少 70% 被用户标为核心或相邻目标；
- 连续 14 天均产生可读取的运行报告。外部站点失败允许存在，但必须被准确记录。

## 分阶段实施

### 阶段 0：恢复可交付基线

修复本地 editable install 和一键演示入口，使现有 release check 能在干净环境中重复执行。只处理影响质量门禁的 lint 和环境问题，不做无关重构。将备份中的 QLoRA、评测、FastAPI 和 Docker 源码恢复到 `visual-web-agent` 的正常 Git 历史，并确认两个仓库的接口和版本关系。

### 阶段 1：建立真实数据协议

定义来源目录、页面快照、结构化岗位、人工标注和失败记录格式；选择首批至少 20 家企业官方招聘入口；为 URL 发现、快照追加、状态迁移和去重建立确定性测试。本阶段不优化模型。

### 阶段 2：连续真实采集

连续 14 天固定运行。每天检查来源状态、证据完整性和失败分类，只修复真实采集暴露的问题。原始快照冻结并支持重放，避免修复前后输入漂移。

### 阶段 3：人工标注与统一评测

完成至少 100 条 ground truth；在固定快照上比较三条采集路径；输出逐样本结果、失败案例、成本、延迟和数据集版本。所有简历指标必须由该版本化 artifact 生成。

### 阶段 4：真实用户闭环

使用用户的真实简历和目标，每天生成去重后的 Top 20 岗位清单。记录用户对推荐、投递意向和失效状态的反馈，但不增加在线学习或复杂推荐模型。最终报告展示发现、筛选、准备投递、误推荐和失效岗位的真实数量及原因。

### 阶段 5：扩展来源

先增加牛客等可追溯转载来源，并核对其官方原始链接；随后将 BOSS、拉勾作为受限平台适配实验。新来源只有通过与官网阶段相同的数据真实性和评测门槛后，才能进入正式指标。

## 测试策略

- 保留 fixture 单元测试，覆盖解析、状态迁移、去重、失败分类和幂等写入；
- 使用冻结的真实页面快照做回归测试，避免测试依赖实时网络；
- 将实时网页运行视为定时采集和 smoke，而不是确定性 CI；
- 对每次真实运行保存数据版本、代码提交、配置摘要和阶段退出状态；
- 对评测报告增加契约检查，禁止缺少数据集版本、样本数、日期、provider 或指标定义的数字进入简历摘要；
- 恢复路径必须验证资源清理、退出状态和失败记录，不能把空结果当作成功。

## 明确不做

本轮不新增工具类型，不做自动投递、自动改写简历、向量数据库、复杂前端、多 Agent 协作或继续微调模型。只有真实评测证明某项是当前瓶颈，并形成单独设计后，才重新考虑。

## 最终交付物

- 真实企业来源目录和访问状态报告；
- 14 天版本化页面快照与运行审计；
- 不少于 100 条岗位人工 ground truth；
- 三条采集路径的统一逐样本评测；
- 每日 Top 20 岗位清单与真实用户反馈；
- 失败案例、成本、延迟和数据边界说明；
- 只引用最终评测 artifact 的 README、项目讲述和简历条目。
