# 真实岗位网站可用性修复计划

> **For agentic workers:** 使用 superpowers:executing-plans，在现有隔离工作区顺序实施。本轮以本计划的真实网页验收为收尾条件；不另起架构项目，不增加并行实现代理。步骤使用 `- [ ]` 记录。

**Goal:** 用户在网页上传真实文字型 PDF 简历，输入岗位和地点后，能够获得有原文依据、链接可打开的真实岗位，以及基于本人简历的匹配说明。

**Architecture:** 保留当前 Streamlit、共享服务、Hybrid runtime、官方 API 适配器、规则匹配与 SQLite。修复既有“指定 URL”和“自动发现”两条入口的数据接线、候选筛选及执行预算，最后整理现有网页输入与结果展示；不重写核心。

**Tech Stack:** 当前 Python 环境、Streamlit、pypdf、现有 HTTP/官方 API 适配器、LangGraph、pytest。

## 一、交付标准：用用户操作和真实结果判定

默认体验目标：AI 应用/Agent 实习、全国、目标 3 条；城市和关键词始终服从用户输入。

必须依次通过两个验收，缺一不称“网站已可用”：

1. **单岗位匹配可用：** 上传真实 PDF，指定一个当前真实、符合输入条件的岗位 URL，网站显示正确岗位和简历匹配说明，原始链接可打开。正常网络下目标 30 秒内返回，慢请求须在总时限内明确结束。
2. **自动搜索可用：** 上传同一简历，通过一个已验证官方来源自动发现并交付岗位。在预先确认至少 3 条符合条件且仍可访问的库存时，目标 3 应交付 3 条；来源变化或库存不足时，交付已确认部分并解释不足。正常网络下目标 60 秒内，默认总时限 90 秒。

验收材料必须是当天真实采集的数据。单 URL 成功不能代替自动搜索成功；Demo、冻结回放、测试通过数、模型对照报告不能代替这两个验收。

本轮使用已有真实网页和适配器，不新增粘贴 JD 模式来绕开自动搜索问题。
