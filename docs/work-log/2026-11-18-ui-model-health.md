# 2026-11-18：侧栏可读性、模型选项与 DeepSeek 能力核验

## 问题

用户截图中，深绿色侧栏里的多个白色输入框、选项按钮和高级设置标题使用浅色文字，内容难以辨认；用户停用 Qwen 后，三个模型菜单仍能选到 Qwen；需要重新确认现有 DeepSeek key 的文本及图片识别能力。

## 根因与修复

### 侧栏样式

原 CSS 的 `[data-testid="stSidebar"] *` 将所有后代文字改为浅色，另有选择框后代和 input 的白字 `!important` 规则，但控件内部背景仍由 Streamlit 浅色主题绘制，形成白底白字。

移除这些全局文字覆盖，改为浅灰白侧栏、深色正文和柔和的绿色提示区域；调整品牌、分区标题和说明文字颜色，让原生控件继续遵循浅色主题。在线 DOM 实测正文颜色为 `rgb(23, 32, 42)`，说明文字为 `rgb(76, 96, 87)`。

按实际颜色计算的对比度：正文 `#17202A` / 白底为 16.45:1；说明文字 `#4C6057` / 侧栏 `#F8FAF9` 为 6.42:1；提示文字 `#274B38` / 提示背景 `#EAF3ED` 为 8.62:1。

### Qwen 选项

原抽取、匹配、规划选择框写死了 `["qwen", "deepseek"]`，未检查配置。首次改为按非空 key 过滤后，线上仍出现 Qwen；实际菜单验证说明云端仍保留了 Qwen 的旧配置。

最终将网页支持列表显式设为 DeepSeek，再检查它是否配置了 key。停用的 Qwen 即使仍有遗留环境变量，也不会重新出现在网页菜单。没有可用配置时禁用模型开关，规则模式仍可使用。历史后端 Qwen 适配器保留兼容，不将“从网页移除”误称为“撤销了供应商平台上的 key”。

在线逐项打开抽取、匹配、规划三个菜单，均只显示一个选项 `deepseek`。新增回归覆盖“没有 Qwen key”和“仍残留旧 Qwen key”两种情况。

### DeepSeek 文本与视觉

先用现有配置访问官方 `/models`，鉴权 HTTP 200；返回的 `deepseek-flash` 声明输入支持 `text` 和 `image`。随后实际执行两个合成测试，而不是仅依赖模型列表声明：

- 文本：请求计算 `41 × 17` 并返回 JSON，模型正确返回 `697`。
- 视觉：发送项目内的 PNG 测试图，提示词不包含答案；模型正确读取数字 `7319`、两个蓝色圆和一个红色矩形。

现有配置使用 `deepseek-v4-flash` 名称，实际响应模型为 `deepseek-flash`。官方 [Vision 文档](https://api-docs.deepseek.com/guides/vision/) 与 [模型列表文档](https://api-docs.deepseek.com/api/list-models/) 说明了当前 Flash 的图像输入接口。

网页增加“检测 DeepSeek 文本与视觉”按钮，使用云端进程中的现有配置，仅发送合成文字和测试图；复用会话用量限制。检测以答案正确为通过标准，HTTP 成功但答案不符也报告失败；错误结果不输出密钥或供应商原始错误正文。

云端首次实测：文本通过 0.94 秒、图片识别通过 1.04 秒。最终版本复测：文本通过 0.64 秒、图片识别通过 1.23 秒。因此无需使用用户提供的备用 key；没有更换现有 key，也没有将备用 key 写入源码或日志。
