# 来源诊断与失效链接收尾

## 范围

实现来源失败诊断、永久失效详情页门禁，并说明搜索条件。云端部署继续暂缓；关键词匹配算法和 Hybrid/HITL 网页集成不属于本轮。

## 已复现的问题

- HTTP 404/410 后仍使用列表 JD，产出“有效岗位”。
- 来源异常与正常空结果都变成空列表，无法诊断。
- 官方来源全部失败后，会悄悄转入 Google 搜索。
- 部分适配器内部吞掉 transport 异常，需要在传输边界记录失败。

## 实现

- `page_reliability.py` 分类 removed/blocked/transient/empty_shell/unknown；诊断不读取任意异常消息，避免泄漏请求或凭据。
- 详情页明确永久失效时抛出 `PageRemovedError`，阻止 HTTP/API 到列表 JD 的兜底；暂时故障保留降级与诊断。
- 下线提示只在短页面开头或标题识别，并要求词边界；正常 JD 讨论异常处理不会误判。
- E1005 是招聘门户内的不可用信号，可能需要切换门户，不按异常文本或因果链判下线。
- 官方来源每次 discover 重置诊断，补足轮合并尝试次数，记录最后一次采样状态和数量。捕获外部异常和适配器内部处理的 transport 失败；有结果时仍记 healthy。
- `UiRunResult.source_diagnostics` 与现有 diagnostics 写入 JSON、持久化副本及网页；分类详情不包含原始异常消息。
- 官方/聚合模式在无候选时结束，不隐式转 Google 搜索。
- 网页和 README 说明地点严格过滤、官方模式关键词并非逐字约束。

## 验证边界

回归测试采用受控来源和页面，不依赖真实招聘网站；本轮不宣称实时全站可达性。缓存仍使用既有 24 小时 TTL，列表自证不等于详情浏览器验证。

## 本地验证（2026-10-05）

- 原行为回归测试先失败：404/410 没有阻止列表兜底、来源诊断缺失、全部来源失败触发 Google 搜索。
- 边界回归先失败：短岗位标题前缀包含“页面不存在”被误判，以及 lister 吞掉 transport 网络错误被误标为空。
- 全量 pytest/coverage：610 passed, 1 skipped；87.16% coverage，超过 70% 门禁。skip 为未配置真实 PostgreSQL 测试数据库。
- `ruff check .`：通过；`git diff --check`：无 whitespace 错误。
- Streamlit AppTest 实际运行 Demo：0 exceptions，四个结果标签正常显示；关键词和地点说明在页面中可见。Demo 包含预期的低置信度岗位过滤诊断，不能假设 Demo 诊断为空。
- 独立代码复核发现并修复 cffi 的 HTTP 错误状态漏报：JSON/HTML 的 403/429/503 必须先拒绝，再执行原有重试与 urllib 降级。六个回归先失败、后通过；复核确认无剩余可操作问题。
